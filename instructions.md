## 0. Два приложения на одном домене

В Next.js это называется Multi-Zones: несколько независимых приложений под одним доменом, каждое отвечает за свои адреса.

| Адрес | Приложение | Как настроено |
|---|---|---|
| `job.rendit.ru/ozon/…` | этот проект | `basePath: '/ozon'` — берётся из адреса сайта в `next.config.ts`; Next сам добавляет `/ozon` к ссылкам, статике и картинкам |
| `job.rendit.ru/…` (всё остальное) | будущий проект с вакансиями | обычное приложение Next без `basePath`, свой репозиторий, свой порт |

- Каждое приложение собирается и запускается отдельно (свой порт), а Nginx по адресу решает, кому отдать запрос ([6.5](#65-dns-nginx-https)).
- Ссылки **между** приложениями — обычным `<a href="/ozon">`, не `<Link>`: переход между приложениями — это полная загрузка страницы.
- `robots.txt` поисковики читают только из корня домена. Наш лежит по адресу `/ozon/robots.txt` — в корень его отдаёт Nginx,
  пока у корневого приложения нет своего; потом в его `robots.txt` нужно перенести строки `Clean-param` и `Sitemap`.
- Домен общий, значит общие и cookie с хранилищем браузера: выбор в баннере cookie (`cookie_consent`) и тема сайта действуют
  в обоих приложениях. В корневом приложении используйте те же имена — или свои, но тогда посетитель увидит баннер дважды.
- У себя на компьютере сайт открывается по адресу `localhost:3000/ozon` (с корня — переадресация).
- Нужен ещё раздел (`job.rendit.ru/wb`) — это третье приложение со своим `basePath` и ещё один `location` в Nginx.

## 3. Юридическое

### 3.1. Самозанятость (НПД)

Приложение «Мой налог» → регистрация по паспорту или через Госуслуги, бесплатно. Налог 4% с физлиц, 6% с компаний и ИП,
лимит 2,4 млн ₽ в год, чек на каждое поступление. Без статуса доход облагается НДФЛ 13% (декларация до 30 апреля),
а регулярная деятельность без регистрации — штраф по ст. 14.1 КоАП. Уточните в правилах каждой программы, как она платит:
часть банков удерживает НДФЛ сама, Ozon Blogger без самозанятости не работает.

### 3.2. Уведомление в Роскомнадзор

Подать **после** выбора домена и хостинга, но **до** запуска и до Метрики: [pd.rkn.gov.ru](https://pd.rkn.gov.ru) →
«Подать уведомление» → вход через Госуслуги.

| Поле | Что указать |
|---|---|
| Оператор | физическое лицо: ФИО, ИНН, паспорт, адрес. Часть сведений попадёт в открытый реестр |
| Цели | статистика посещаемости; ответы на обращения; договоры на разработку сайтов |
| Данные | ФИО, телефон, e-mail, имя в Telegram; идентификаторы cookie, IP-адрес, сведения о браузере и устройстве |
| Субъекты | посетители сайта; обратившиеся к оператору; заказчики |
| Основания | 152-ФЗ, ст. 6 ч. 1: п. 1 (согласие), п. 5 (договор), п. 7 (законный интерес) |
| Действия | сбор, запись, систематизация, накопление, хранение, уточнение, извлечение, использование, передача (предоставление), блокирование, удаление, уничтожение; смешанная обработка, с передачей по сети интернет |
| Меры защиты | ответственный — сам оператор; политика опубликована; пароли и двухфакторный вход; доступ только у оператора |
| Хранение | Россия: адрес дата-центра хостинга (спросить у провайдера) и почта Mail (Москва) |
| Трансграничная передача | нет (пока не подключён Google Analytics) |
| Даты | начало — дата запуска; прекращение — ликвидация сайта или отзыв согласия |

Запись в реестре появляется примерно через месяц. Изменились сведения (хостинг, новый сервис, форма) — письмо об изменениях
в течение 10 рабочих дней. Включите двухфакторный вход на почте и хостинге: в уведомлении вы это заявляете.

### 3.3. Маркировка рекламы (erid)

Реферальные ссылки и код приглашения на публичном сайте — реклама (ст. 18.1 ФЗ «О рекламе»). Пометка «Реклама»
и рекламодатель у каждой уже есть; не хватает erid.

1. Спросить в каждой программе, не выдаёт ли она erid сама (Ozon Blogger выдаёт).
2. Если нет — зарегистрироваться в аккредитованном ОРД (список на сайте Роскомнадзора) и зарегистрировать креативы.
3. Вписать erid в конфиги ([2.2](#22-когда-появятся-данные)).
4. Уточнить в ОРД или у юриста, касается ли вас сбор 3% с доходов от интернет-рекламы.

### 3.4. Документы сайта

`/menu/about`, `/menu/privacy`, `/menu/cookies`, `/menu/terms`, `/menu/ads` — тексты в `messages/*.json` → `LegalDocs.*`,
владелец, контакты и хостинг подставляются из `src/config/legal.ts`. Редакция от 12.10.2026. Что в них заявлено —
и что должно оставаться правдой:

- на сайте нет форм и регистрации; ставится одна cookie — `cookie_consent` (выбор в баннере), тема хранится в браузере;
- журналы сервера хранятся не дольше 30 дней ([6.6](#66-журналы));
- аналитика включается только после «Принять»; сейчас счётчики не подключены;
- размер вознаграждения по программам Ozon Банка и Ozon Blogger не публикуется.

Добавили форму, счётчик, сервис или сменили хостинг — обновить политику, `LEGAL_UPDATED_AT` и подать письмо в РКН.

## 6. Сервер

Ниже `1.2.3.4` — IP сервера, `deploy` — пользователь сайта. Этот проект слушает порт **3001**, порт 3000 оставлен
корневому приложению с вакансиями.

### 6.1. Первый вход, пользователь, защита

```bash
ssh root@1.2.3.4
apt update && apt upgrade -y
timedatectl set-timezone Europe/Moscow
adduser deploy && usermod -aG sudo deploy
mkdir -p /home/deploy/.ssh && cp /root/.ssh/authorized_keys /home/deploy/.ssh/
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh && chmod 600 /home/deploy/.ssh/authorized_keys
```

В **новом** окне проверить `ssh deploy@1.2.3.4`. Только после этого в `/etc/ssh/sshd_config` поставить
`PermitRootLogin no` и `PasswordAuthentication no`, затем:

```bash
sudo systemctl restart ssh
sudo ufw allow OpenSSH && sudo ufw enable
sudo apt install -y fail2ban
```

### 6.2. Swap (при 2 ГБ RAM и меньше — сборка ~1 900 страниц может не поместиться в память)

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### 6.3. Node.js 24 LTS, код, сборка

```bash
curl -fsSL https://deb.nodesource.com/setup_24.x -o nodesource_setup.sh
sudo -E bash nodesource_setup.sh
sudo apt install -y nodejs git
sudo mkdir -p /var/www/ozon && sudo chown deploy:deploy /var/www/ozon
git clone https://github.com/Relux777/ozon_v5.git /var/www/ozon
cd /var/www/ozon
npm ci
npm run build
```

Репозиторий приватный — вместо `https://` клонировать по SSH с ключом из GitHub → Settings → Deploy keys (только чтение).

### 6.4. Автозапуск

`sudo nano /etc/systemd/system/ozon.service`:

```ini
[Unit]
Description=Ozon Rabota (Next.js)
After=network.target

[Service]
Type=simple
User=deploy
WorkingDirectory=/var/www/ozon
Environment=NODE_ENV=production
ExecStart=/usr/bin/node node_modules/next/dist/bin/next start -p 3001 -H 127.0.0.1
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ozon
sudo systemctl status ozon
```

Логи: `journalctl -u ozon -f`. `-H 127.0.0.1` — Next слушает только локально, снаружи к нему ходит Nginx.

### 6.5. DNS, Nginx, HTTPS

У регистратора: запись `A` для `job` → `1.2.3.4`. Когда `ping job.rendit.ru` показывает IP сервера:

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo ufw allow 'Nginx Full'
sudo nano /etc/nginx/sites-available/ozon
```

Сначала временный конфиг — он нужен, чтобы certbot выпустил сертификат:

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name job.rendit.ru;
    location / { proxy_pass http://127.0.0.1:3001; proxy_set_header Host $host; }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/ozon /etc/nginx/sites-enabled/
sudo rm /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d job.rendit.ru
```

Затем заменить содержимое файла на итоговое (сертификат продлевается сам):

```nginx
# раздел об Ozon (этот проект)
upstream ozon_next {
    server 127.0.0.1:3001;
    keepalive 32;
}

# http → https
server {
    listen 80;
    listen [::]:80;
    server_name job.rendit.ru;
    return 301 https://job.rendit.ru$request_uri;
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name job.rendit.ru;
    ssl_certificate /etc/letsencrypt/live/job.rendit.ru/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/job.rendit.ru/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

    # включить, когда https работает везде (браузеры запомнят на год)
    # add_header Strict-Transport-Security "max-age=31536000" always;

    gzip on;
    gzip_min_length 1024;
    gzip_types text/plain text/css application/javascript application/json application/xml image/svg+xml;

    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;

    # всё, что начинается с /ozon, — этому проекту
    location /ozon {
        proxy_pass http://ozon_next;
    }

    # ── пока корневого приложения с вакансиями нет ──
    # robots.txt поисковики читают только из корня домена — отдаём наш
    location = /robots.txt {
        proxy_pass http://ozon_next/ozon/robots.txt;
    }
    # корень домена временно ведёт в раздел (302 — не «навсегда»)
    location = / {
        return 302 /ozon;
    }
    # ── когда появится корневое приложение (порт 3000): убрать два блока выше и раскомментировать ──
    # location / {
    #     proxy_pass http://127.0.0.1:3000;
    # }
}
```

### 6.6. Журналы

В политике заявлено: журналы сервера — **не дольше 30 дней**. Nginx в Ubuntu хранит 14 дней (`/etc/logrotate.d/nginx`,
`rotate 14`) — не увеличивать больше 30. Журнал systemd: в `/etc/systemd/journald.conf` строка `MaxRetentionSec=30day`,
затем `sudo systemctl restart systemd-journald`.

### 6.7. Обновление сайта

`nano ~/deploy.sh`, затем `chmod +x ~/deploy.sh`:

```bash
#!/usr/bin/env bash
# Обновление сайта: забрать код, собрать, перезапустить. Упала сборка — скрипт остановится до перезапуска
set -euo pipefail
cd /var/www/ozon
git pull --ff-only
npm ci
npm run build
sudo systemctl restart ozon
echo "Готово: $(git log -1 --format='%h %s')"
```

Каждое обновление: отправить изменения на GitHub → на сервере `~/deploy.sh`. Пока идёт сборка (1–2 минуты), часть страниц
может открываться с ошибкой — обновлять в тихое время. Поменяли `.env.production` — тоже нужна пересборка.

      в sitemap и в коде страницы (`canonical`, `hreflang`) — адреса вида `https://job.rendit.ru/ozon/…`;

- [ ] [PageSpeed Insights](https://pagespeed.web.dev) для главной и страницы города (телефон).

### 7.2. Поисковики

1. [Яндекс Вебмастер](https://webmaster.yandex.ru) → добавить сайт → «Мета-тег»; [Search Console](https://search.google.com/search-console)
   → «Ресурс с префиксом URL» → «Тег HTML». Из обоих тегов взять значение `content`.
2. Вписать в `src/config/site.ts` → `SEARCH_VERIFICATION = { yandex: '…', google: '…' }`, выложить, нажать «Проверить».
3. Сайт в панелях — `https://job.rendit.ru` (весь поддомен: поисковики подтверждают права по главной странице, тег
   выводит и наш раздел). Пока корень домена переадресует в `/ozon`, проверка мета-тегом может не пройти — тогда выбрать
   подтверждение DNS-записью. В обеих панелях добавить `https://job.rendit.ru/ozon/sitemap.xml`. В Вебмастере: региональность — Россия.

### 7.3. Яндекс Метрика

Только после уведомления РКН. [metrika.yandex.ru](https://metrika.yandex.ru) → «Добавить счётчик» → **Вебвизор выключить**
(в политике и согласии он не описан). Номер счётчика — в `src/config/legal.ts` → `YANDEX_METRIKA_ID = '12345678'`.
Код счётчика в страницы вставлять не нужно: он встроен и включается после «Принять». Строка «счётчики не подключены»
в документах исчезнет сама; обновить `LEGAL_UPDATED_AT`.
