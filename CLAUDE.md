# Ozon V5 — контекст для Claude

> Обновлено 11.10.2026. Прежняя подробная версия (история правок и разборы багов по датам) — в истории git

## 1. Проект

Неофициальный информационный сайт о подработке на складах Ozon через приложение **Ozon Job** (ГПХ, самозанятость, ИП;
оплата за слот). Владелец — не Ozon. Доход владельца — реферальные программы: код приглашения Ozon Job (`QK3HMR42`) и
приглашения Ozon Банка («Акции»). Аудитория — Россия и СНГ, **9 языков**: ru (основной), uz, tg, hy, az, ka, ky, kk, en
(tg и en добавлены 29.09.2026, PR #2).

Страницы: `/` главная · `/sklad` поиск города · `/sklad/<город>` склады города · `/stocks` акции · `/menu` хаб ·
`/menu/level` рейтинг · `/menu/support` вопросы · `/menu/cooperation` заказ сайта ·
`/menu/{about,privacy,cookies,terms,ads}` документы (переведены на 9 языков, noindex; юридически значим русский текст).

## 2. Как работать с владельцем

- Общаться **на русском**, кратко; в конце — что сделано и что осталось. Данные не выдумывать, ошибки признавать прямо.
- **Не коммитить и не пушить без просьбы.** Код и конфиги менять только с согласия.
- Владелец правит файлы параллельно (локально и на GitHub) — перед правкой перечитывать файл, его изменения не откатывать.
- Стили — классами ReluxCode в разметке (общий шаблон этого и других проектов владельца), в `style.scss` — только то,
  чего в ReluxCode нет и что специфично для этого сайта (см. §5).
- Юридическая осторожность — см. §7. Антибот Ozon не обходить, внутренние API Ozon не дёргать.
- Ссылки на файлы в ответах — markdown с относительным путём.

## 3. Стек

Next.js **16.3.4** (App Router, Turbopack) — не тот Next, что в обучающих данных: перед незнакомым API читать
`node_modules/next/dist/docs/`. React 19.2 + React Compiler. `next-intl` 4, `next-themes`, Sass + CSS Modules + ReluxCode,
SVGR (`*.svg` → React-компонент), Biome, TypeScript strict, алиас `@/*` → `src/*`.

Особенности Next 16: `src/proxy.ts` вместо middleware; `params`/`searchParams` — Promise; у `error.tsx` проп `retry`;
`next/root-params` не работает в Server Actions и Route Handlers; `next lint` нет (Biome).

Команды: `npm run dev` · `npx next build` · `npx next start -p <порт>` · `npm run lint` (Biome, только линтер) ·
`npm run check` (линтер + формат + порядок импортов, без записи) · `npm run format` (переформатировать — затронет почти все файлы,
делать отдельным коммитом). Формат в `biome.json` = стиль кода проекта: 4 пробела, одинарные кавычки (и в JSX), строка до 160,
`;` и запятые в конце; JSON не форматируется (словари держат свою разметку).
`npx tsc --noEmit` — **после** `next build`/`next dev` (на свежем клоне нет `next-env.d.ts`, будут ложные ошибки про `*.webp`).

## 5. Стили: ReluxCode + style.scss

### 5.1 Главное правило — где что писать

| Что | Где |
|---|---|
| Раскладка, отступы, размеры, радиусы, шрифты, цвета из токенов, тени, blur, позиционирование, hover-эффекты | **классы ReluxCode в разметке** (`className='flex align-center gap-10 pd-20 br-20 bg-3-100 shadow-3'`) |
| Не хватает значения в шкале (например, `gap-6`) | **дописать значение в массив** в `_utilities.scss`, поднять версию в шапке `ReluxCode.scss` (сейчас **v2.2.12**) и строку в журнал |
| Нужна новая универсальная утилита (годится любому проекту) | в ReluxCode: `_layout.scss` / `_utilities.scss` / `_animations.scss` / `_media.scss` |
| Только то, что есть у этого сайта: градиенты, `::before/::after`, `@keyframes`, `@container`, `grid-template-*`, точные смещения, состояния (`:checked`, `.tip-open`, `:has()`), оформление конкретного блока | **`style.scss`** |
| Стили общего компонента из `components/ui/` | партиал `_<имя>.scss` в папке компонента + строка `@use` в начале `style.scss` |
| Стили одного компонента, которым нужна изоляция (Modal, NavBar, Header) | `*.module.scss` рядом с компонентом (миксины — относительным путём `@use "../../assets/scss/mixins"`) |

Перед тем как написать свойство в `style.scss`, проверить: нет ли такого класса в ReluxCode? Если есть — класс в разметку, а не CSS.
ReluxCode — **общий шаблон для всех проектов владельца**: дополнять и улучшать можно, неиспользуемые классы не удалять, проектную
специфику туда не класть. Подключение в `layout.tsx`: `ReluxCode.scss`, затем `style.scss`.

### 5.2 Цвета и переменные (`_variables.scss`)

Цвета — **каналы RGB без `rgb()`**, прозрачность задаётся при использовании: `rgb(var(--bg-5) / 50%)`. Тёмная тема — `[data-theme='dark']`
(next-themes), токены переопределяются там же; свои цвета под тему писать тоже через `[data-theme='dark'] &`.

| Токен | Светлая | Тёмная | Смысл |
|---|---|---|---|
| `--bg-phone` | 237 237 237 | 0 0 0 | фон страницы (`body`) |
| `--bg-1` | 255 255 255 | 0 0 0 | «фон» — инвертируется |
| `--bg-2` | 0 0 0 | 255 255 255 | «текст» — инвертируется (`body` = `--bg-2 / 70%`) |
| `--bg-3` | 255 255 255 | 14 14 14 | карточки (`bg-3-100`) |
| `--bg-4` | 60 130 255 | 103 158 254 | светлый синий |
| `--bg-5` | **0 91 255** | 0 91 255 | **фирменный синий `#005bff`**, одинаков в обеих темах |
| `--bg-6` | 255 255 255 | 255 255 255 | всегда белый (текст на синем) |
| `--text-5` | = `--bg-5` | 77 148 255 | синий **текст** (`.color-5-*`; в своих правилах — `rgb(var(--text-5, var(--bg-5)))`): в тёмной теме светлее ради контраста ≥ 4,5:1 |

Прочие: `--base-font-size: 13px`, `--header-h: 60px`, `--focus-ring` (= `--bg-5`), `--scrollbar-*`, стекло `--glass-*`
(для `shadow-1/2/4`). В `style.scss` — SCSS-переменные оттенков градиента акций: `$promo-blue-dark #0044c2`,
`$promo-blue-light #3f9bff`, `$promo-navy #0a1f44`; акцент карточки — CSS-переменная `--accent` (`.icon-badge`, `.accent-text`,
`.accent-fill`). Белый текст на синем блоке — `rgb(255 255 255 / 90%)`. Шрифт — Geist (`--font-geist`), ka/hy — Noto через `body:lang()`.

задано классом, — иначе класс в разметке «молча» перестаёт работать.

### 5.4 Правила

- `:hover` — только через `@include mixins.hover {…}` (на телефоне залипает); пара для тача — `mixins.touch-press`.
- Значение не из шкалы — округлить до ближайшего, если визуально не критично; иначе добавить в шкалу. Класс, которого нет в CSS,
  молча не работает: проверять — собрать классы из `*.tsx` и сравнить с селекторами CSS, скомпилированного `npx sass`
  (`ReluxCode.scss` + `style.scss` + `*.module.scss`).
- Первая `<section>` в `<main>` растянута почти на весь экран — на страницах со списком держать всё в одной секции.
- Не писать рядом `backdrop-filter` и `-webkit-backdrop-filter` — минификатор оставит только префиксный (Chrome его игнорирует).

**Частые ловушки:**
- `.flex` и `.inline-flex` в ReluxCode — **`flex-wrap: wrap` по умолчанию**: чипы «✓ текст» и строки «заголовок + иконка» разваливаются
  на телефоне — добавлять `nowrap`.
- Ряд `.flex` с колонками `.f-w-*` — всегда с `.row-flush` (и первый экран `Hero`): без него колонки на 10px правее
  заголовка секции — на телефоне текст и карточки стоят «лесенкой».
- Grid/flex с «широким» потомком раздувает мобильную вёрстку — `min-width: 0` на детях. Проверять переполнение через
  `document.documentElement.scrollWidth > clientWidth`.
- Любой новый `position: fixed` элемент внизу экрана — `z-20` (NavBar на `z-10`, баннер cookie — `z-30`,
  полноэкранный просмотр фото PhotoSlider — `z-40`, уведомления ui/alert — 50, «Перейти к содержимому» — 100).
- Цвет панели браузера: `THEME_COLORS` в `config/site.ts` — его берут `viewport.themeColor` (системная тема) и `ThemeSwitch`
  (тема, выбранная на сайте).
- Равная специфичность «закрытого» и «открытого» состояний модалки ломалась от порядка правил — закрытое писать через `:not(.active)`.
- Если на `next dev` не видно новых правил в уже подключённом `.module.scss` — проверить на `next build` + `next start`, а не чинить вслепую.
- `.promo` с `@container`-запросами внутри — обязательно `container-type-inline`.
- NavBar: ширина пункта `--item-width` (сейчас 74px, `nav.module.scss`), подпись 12px с `.truncate` — длинные подписи (hy, az, ka, en)
  обрезаются многоточием. От высот NavBar зависят `bottom` у `.float-btn` и баннера cookie — менять вместе.
- Плавная прокрутка якорей — `data-scroll-behavior="smooth"` на `<html>` (требование Next 16, иначе предупреждение в консоли).

## 6. Переводы (i18n)

- Новый ключ — во **все 9** `messages/*.json`, иначе `tsc`/сборка упадёт (`messages.check.ts`).
- Новый язык = словарь `messages/<код>.json` + `routing.ts` + `messages.check.ts` + `config/languages.ts` (флаг в `svg/Language/`)
  + OG-локаль в `lib/seo.ts` (`OG_LOCALES`). Списки `STOCKS_LOCALES`/`LEVEL_LOCALES` = `routing.locales` — подхватят сами.
- Клиенту отдаются только `NavBar`, `A11y`, `SkladSearch`, `ErrorPage` (`clientMessages` в `layout.tsx`). Клиентский компонент с
  `useTranslations('X')` — добавить `X` туда; лучше передавать подписи пропсами с сервера (так сделаны CookieBanner, CopyCode, калькулятор).
- Правила по контенту: сначала пишем в `ru.json`. Если владелец не просил перевод — остальные языки синхронизировать по структуре
  (временный русский плейсхолдер), потом перевести отдельным заходом. Проверка непереведённого — сравнить строки с ru (в ky/kk по фразам).
- SEO-строки: `title` ≤ ~60 символов, `description` ≤ ~160 на всех языках (длиннее — только у регионов с длинным названием).
- Названия городов: на en/uz/az — латиницей (`getCityName` → `latinName`: «Kazan», «Qozon», «Moskva vilayəti»; поиск на `/sklad`
  ищет и по русскому названию), на остальных языках — русские. Адреса складов и населённые пункты в тексте — всегда по-русски.
  ICU: `{count, plural, …}`, `{x, number}`. Длительности — аргументами `{n}`/`{unit}`, не готовой строкой.
- `ru.json` местами размечен вручную (короткие массивы и объекты в одну строку) — скриптом не перезаписывать его целиком через
  `JSON.stringify`, а менять нужные строки/блоки в тексте. Остальные словари — стандартный JSON с отступом 2, CRLF.
- Переводы делал Claude — нужна вычитка носителями. Старые скрипты `*-i18n.cjs`, `sup-apply.cjs` **не запускать** — затрут переводы.

## 7. Юридические правила (соблюдать)

1. Везде: независимый сайт, не Ozon; «Ozon — товарный знак ООО «Интернет Решения»».
2. Промо-блоки — пометка «Реклама», раскрытие вознаграждения, рекламодатель с ИНН; поле `erid` в config (пока пусто).
3. Доходы — только «до/от …», «по данным Ozon, не гарантировано», с датой. Суммы и цифры — только проверенные, с источником.
4. Банк/кредитка: не обещать доход; условия, влияющие на стоимость кредита, — только вместе с ПСК; ставки по вкладам не пишем.
5. Никаких выдуманных отзывов, фото/логотипов/скриншотов Ozon; нет ограничений по полу/возрасту; не выдавать себя за работодателя.
6. Аналитика — только после «Принять» в баннере; перед подключением Метрики — уведомление в РКН. GA — трансграничная передача, лучше не подключать.
7. Суммы вознаграждения владельца не публиковать. Документы и схему рекламы — показать юристу.

## 8. Данные и факты

- **Склады:** источник — career.ozon.ru (вакансии **в штат**, позиция «Оператор склада»), выгрузка `updatedAt` в `warehouses.json`
  (последняя — 10.10.2026: 58 складов, 194 города из 360; у остальных 136 вакансий на Ozon не было, ещё в 30 — только другие
  позиции, их не берём). Склад = одна запись: `address` (текст Ozon), `fullAddress` (с регионом и районом), `income {from?, to?}`,
  `perks`, `cities[]` (наши slug'и). Опечатка в slug роняет сборку — так и задумано. Через Ozon Job складов больше (500+).
- **Как обновлять склады:** список городов — в HTML любой страницы города (`window.sigma.multipageConfig.state`, группа ссылок
  `/<город>/sklad`; текущего города в ней нет). Карточки подгружает сама страница — открывать `career.ozon.ru/<город>/sklad`
  в браузере по одному городу и читать с экрана: выбранную позицию, у каждой карточки условия, адрес, доход (ждать карточки
  или заглушку «Попробуй поискать позиции в других городах»). Их внутренний API (`sigma-bff-api`) не вызывать, антибот не обходить;
  фреймы сайт не разрешает. Итог сверять с общей страницей `career.ozon.ru/sklad/` (там все карточки позиции сразу).
  У склада, который уже был в базе, `fullAddress` сохранять; у нового — текст Ozon + регион и пометка, что по картам не сверен.
- **Ozon Job** (docs.ozon.ru/job-ff-help): с 16 лет для граждан РФ; регистрация через Госуслуги или Ozon Банк; оплата = пики × тариф;
  на карту Ozon Банка через 3 ч («Новичок», «Бриллиант») или 12 ч, в другие банки — по вторникам; слоты 4/6/8/12 ч;
  самозанятым налог удерживает Ozon Job; смена типа сотрудничества — до 10 раз.
- **«Приведите друга» Ozon Job:** новичок получает 1 000 ₽ (крупные склады), 2 000 ₽ (дарксторы fresh), 5 000 ₽ («Новая Рига»)
  после заданий на 30 000 ₽ за 30 дней. `PROMO.userBonus = 5000` — выводится как «до 5 000 ₽» (по экрану «Приведите друга»
  в приложении, 02.10.2026: другу — до 5 000 ₽, пригласившему — до 20 000 ₽; точная сумма зависит от склада).
- **Ozon Банк «Приведи друга»:** суммы индивидуальные; условия по каждой программе — в `config/referrals.ts` и `StocksPage.*`.
- Даты сверки: `HOME_CHECKED_AT`, `SUPPORT_CHECKED_AT`, `APP_SCREENS_TAKEN_AT` (`config/site.ts`), `REFERRALS_CHECKED_AT`,
  `RATING_CHECKED_AT`, `LEGAL_UPDATED_AT` — обновлять при каждой сверке (идут в sitemap; у страницы города — самая поздняя
  из дат складов, главной и скриншотов).

## 9. SEO и производительность

- Метаданные только через `buildPageMetadata` (canonical, hreflang, OG с `public/og.jpg`; `ownImage: true` — у страницы своя
  картинка превью). Непереведённые языки страницы — через `locales`. Скрытые страницы — `noindex, follow` (ссылки с них учитываются).
- Язык определяет только адрес: `localeDetection: false` в `routing.ts` (без редиректа по языку браузера и cookie — так советует Google);
  cookie языка не ставится (`localeCookie: false`).
- Заголовки главной (11.10.2026): title «Работа на складе Ozon: оператор склада, подработка в Ozon Job», h1 «Работа на складе Ozon:
  подработка через приложение Ozon Job» — ключи «работа на складе» и «оператор склада» вместе с «подработка» и «Ozon Job».
  «Вакансия» и «ежедневные выплаты» в заголовки не возвращать: сайт не работодатель (§7 п. 5), а выплаты — от 3 часов, а не «каждый день» (п. 3).
- JSON-LD: `WebSite` + `SearchAction` (главная → `/sklad?q=`; `CitySearch` читает `?q=` и пишет его обратно), `ItemList` городов
  со складами на `/sklad`, `BreadcrumbList` на внутренних.
- `robots.txt` — `src/app/robots.txt/route.ts`: `Clean-param` для utm/yclid/gclid/fbclid (иначе ссылки с метками — дубли у Яндекса).
- FAQPage — только настоящие вопросы и только на одной странице. Реферальные ссылки — `rel="sponsored nofollow noopener noreferrer"`.
- Картинки — только webp нужного размера (исходники PNG не импортировать), `sizes` по реальной ширине.
- Стекло (`backdrop-filter`) на телефонах дорогое — декоративное помечать `.touch-no-blur`.
- Декоративные картинки на первом экране (пятна BackgroundDecor) — хранить маленькими (сейчас 1/8 размера): растянутая
  картинка считается для LCP не больше своего размера и не «перебивает» заголовок. В 1/4 пятно становилось LCP (~4 с).
- Next отдаёт картинки в AVIF, где браузер его понимает (`images.formats` в `next.config.ts`), иначе WebP.
- `NEXT_PUBLIC_SITE_URL` обязательно задать на сервере, иначе canonical уйдёт на запасной домен из `config/site.ts`.

## 10. Проверка перед отчётом

1. `npx next build` (затем `npx tsc --noEmit`).
2. `npx next start -p <порт>` и осмотр в браузере: десктоп и телефон, светлая и тёмная тема. Модалки и анимации — на активной вкладке
   и реальным кликом, со скриншотом.
3. Остановить сервер. Коротко отчитаться: что сделано, что осталось.
