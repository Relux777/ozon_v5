## 1. Что за проект

**Мультиязычный рекламный лендинг для привлечения людей на работу в Ozon** (склады, курьеры, подработка через приложение
Ozon Job). Это **неофициальный информационный сайт** (владелец не Ozon и не его представитель).

**Бизнес-модель владельца:** реферальный заработок — пользователь скачивает приложение Ozon Job, вводит промокод
(в примерах `J485DG`) и получает бонус (в примерах 2 000 ₽), владелец получает своё вознаграждение (эту сумму на сайте
**не показываем**). Планируются также реферальные ссылки (Ozon Карта и т.п.).

**Аудитория:** соискатели из России и СНГ (языки: ru, uz, hy, az, ka, ky, kk).

**Ключевые страницы:**
- главная `/` — привлечение, цифры, промокод (сейчас в доработке, см. §12);
- `/sklad` — список городов с поиском; `/sklad/<город>` — страница города: адреса складов, доход, бонусы (SEO под каждый город);
- `/menu`, `/a` — заглушки; `/test1`, `/test2` — **дизайн-макеты** (noindex), из них владелец переносит блоки в основные файлы.

## 2. Как работать с владельцем (предпочтения — важно)

- **Общение на русском.** Кратко, по делу; в конце — что сделано и что осталось. Не выдумывать данные; ошибки признавать прямо.
- **«Не сломать код».** Перед крупными правками — сравнивать «до/после» (для SCSS есть приём сравнения скомпилированного CSS, §14).
  После правок обязательно: `npx tsc --noEmit`, `npx next build`, проверка в браузере.
- **Стили:** раскладку делать **утилитами `ReluxCode`** (`.flex`, `.f-w-*`, `.gap-*`, `.bg-*`, `.br-*`…), в `module.scss` — только то,
  чего нет в ReluxCode. Владелец сам много правит стили и добавляет утилиты — не переписывать его классы без просьбы.
- **Владелец правит файлы параллельно с Claude.** Перед `Write`/`Edit` перечитывать файл (Write падает с «file modified since read»).
  Если файл изменён им — считать это актуальным состоянием и не откатывать.
- **Изменения не коммитить** без просьбы. `git` в PowerShell **не в PATH** (команда `git` не найдена) — статус смотреть иначе.
- **Юридическая осторожность:** владелец явно просил «не попасть под закон». См. §11 — не нарушать эти правила.
- Ссылки на файлы в ответах — markdown-ссылками с относительным путём.
- Автоматизацию **антибот-защиты Ozon не обходить** (§10).

## 5. Интернационализация

- **Локали:** `ru` (по умолчанию, **без префикса** в URL), `uz`, `hy`, `az`, `ka`, `ky`, `kk` (с префиксом `/uz/...`). `localePrefix: 'as-needed'`.
- Локаль в компонентах: серверные — `getTranslations({locale, namespace})` / `getFormatter`; клиентские — `useTranslations`.
  **Клиенту отдаются только выбранные разделы** (`layout.tsx` → `clientMessages`): `NavBar`, `A11y`, `ErrorPage`, `SkladSearch`, `Promo`.
  Новый клиентский компонент с `useTranslations('X')` ⇒ **добавить `X` в `clientMessages`**, иначе рантайм-ошибка.
- **Добавляя ключ — добавлять во ВСЕ 7 файлов** `messages/*.json`, иначе `tsc`/`next build` упадёт (`messages.check.ts`).
  Недостающий ключ на рантайме подтягивается из `ru` (`request.ts`) — это только страховка.
- Тексты на других языках писались Claude — **нужна вычитка носителями** (особенно hy, ka, ky, kk и юридические формулировки).
- ICU: `{count, plural, one {…} few {…} many {…} other {…}}` (ru), `{x, number}` для чисел. Апострофы в uz (`o'`) безопасны, пока не стоят перед `{`/`}`.
- Названия городов **везде русские** (данных на других языках нет); в шаблонах: ru «г. Казань», uz «Казань sh.», az «ş.», hy «ք.», ka «ქ.», ky «ш.», kk «қ.».
- Бренд в словарях пока не единый: «Озон Работа», «Ozon Ish», «Озон Жумуш», «Ozon Աշխատանք», «Ozon სამუშაო», «Ozon İş», «Ozon Жұмыс» — решение за владельцем.
- Переключение языка: модалка → `router.replace({pathname, query}, {locale})` (query сохраняется).

## 7. Данные раздела «Склады» (важно)

**Источник:** публичные страницы `career.ozon.ru` (общая `/sklad/` с позицией «Оператор склада» и страницы городов `/{slug}/sklad`).
Дата выгрузки — поле `updatedAt` в `warehouses.json` (сейчас **2026-09-19**). Доходы и адреса у Ozon меняются — данные устаревают.

**`cities.json`** — массив `[ozonSlug, name]`, 418 записей (включая регионы: «Московская область», «Республика Татарстан»…). Тестовая запись
«тест панфилов» исключена. Наш URL-slug = `ozonSlug.toLowerCase().replace(/_/g,'-')`; ссылка на оригинал строится по `ozonSlug`.

**`warehouses.json`:**
```jsonc
{ "updatedAt": "YYYY-MM-DD", "source": "…",
  "warehouses": [
    { "address": "…", "income": { "from"?: 90000, "to"?: 160000 },   // хотя бы одно поле
      "perks": ["transport","training","meal","dms"],
      "cities": ["kazan","zelenodolsk","respublika-tatarstan"] }      // наши slug'и, на чьих страницах показывается склад
] }
```
**Добавить/изменить склад = править одну строку.** `lib/sklad.ts` при загрузке **бросает ошибку**, если в `cities` есть slug, которого нет в `cities.json`.

**Текущий охват:** 53 склада, 65 страниц городов/регионов с данными (из 418). Остальные города — «Адреса уточняются», `noindex`.
**Данные неполные:** общий список из 53 не исчерпывающий (нашлось расхождение: у Благовещенска (Амур) есть склад, которого нет в общем списке).
Привязка склад→город сделана по адресу и проверена страницами Ozon (Москва: 16, СПб: 5, Казань: 3, Екатеринбург: 2, Ростов: 2 …). Ozon группирует по агломерации:
страница города показывает склады рядом (например, Ногинск → Ногинск + Старая Купавна), региональные страницы зеркалят склады региона.
Осторожно: «Благовещенск» — два города (`blagoveschensk` = Башкортостан, склад на ул. Социалистической; `blagoveschensk-amur` = Амурская, ул. Промышленная 31/2).

**API `lib/sklad.ts`** (только сервер!): `getCity`, `getCityStats` (count, min из явных `from`, max из `to`, average по `to` округлённо до 1000, perks), `getCityIndex()`
(лёгкая проекция `{slug,name,count}` для клиентского поиска), `getCitiesWithWarehouses`, `getOzonCityUrl`, `DATA_UPDATED_AT`.
Доход показывается как «от X до Y» / «до Y» / «от X» (ключи `incomeRange/incomeUpTo/incomeFrom`); в заголовки/описание подставляется готовая строка `{income}`.

Реальные агрегаты на 2026-09-19: макс. «до» **160 000 ₽** (Зеленодольск/Казань), типично **126 000** (МО), среднее/медиана «до» ≈ 112–113 тыс., 43 из 53 складов ≥ 100 тыс.,
транспорт у 51, питание у 52, ДМС у 48, обучение профессии у 28.

## 8. Дизайн-система ReluxCode (`src/assets/scss/`)

Собственный «bootstrap» владельца, переиспользуется в его других проектах (**неиспользуемые классы оставлять**). Подключается в `layout.tsx`:
`ReluxCode.scss`, затем `style.scss` (проектные правки).

**Файлы:** `_layers.scss` (порядок слоёв `base < layout < utilities < animations`, объявляется первым) · `_variables.scss` (цвета-каналы, темы) ·
`_mixins.scss` · `_base.scss` · `_layout.scss` · `_utilities.scss` · `_animations.scss` · `_media.scss` (**намеренно вне слоёв** — иначе `.none-max-620` и `.f-w-*` не перебьют `.flex`).
Версия v2.1.0 (журнал в шапке `ReluxCode.scss`).

**Переменные (темы):** `--bg-phone`, `--bg-1…6` (каналы «R G B», использовать `rgb(var(--bg-5) / 50%)`), `--focus-ring`, `--header-h`, `--base-font-size:13px`, стекло `--glass-*`.
`--bg-5 = 0 91 255` (фирменный синий #005bff). Светлая/тёмная тема — `[data-theme='dark']` (+ `color-scheme`).

**Раскладка:** `.container` (max-width по брейкпоинтам, safe-area) · `.flex` (**wrap по умолчанию**; модификаторы `.align-center/.align-start/.justify-between/.nowrap/.column/…`) ·
`.f-w-1…12` (ширина колонок; дети `.flex` получают `padding-inline:10px`; на <990px все `f-w-*` = 100%) · `.grid` · `.block/.none/.flex-1/.shrink-0` ·
**внимание:** вложенный `.flex`-список внутри колонки смещает карточки на 10px — компенсируем в module `margin-inline:-10px`.

**Утилиты (шкалы настраиваются через `@use "utilities" with (...)`, значения на момент написания):**
padding `pd-{0,10,20}`, `pl-{0,30}`, `px-{0,24}` · margin-bottom `mb-{0,7,15,20}` · gap `gap-{2,3,5,7,10,15}` · font-size `font-{14,16,22,24,36}` · weight `font-w-{400,500}` ·
radius `br-{8,20,36}` · height `h-{0,4,36,46,60}`, `h-full`, `h-100dvh` · width `w-{0,36,40}`, `w-full`, `max-w-60-ch` · z `z-{10,20,30}`, `z-minus` ·
цвета фона `bg-{1,2,3,5}-{3,7,10,20,50,80,100}` и `hover-bg-…` · цвет текста `color-{1,2,4,5,6}-{10,80,90,100}` · рамки `border-1px-{1,2}-{10,20}` ·
тени `shadow-1…5` (стеклянные) · `blur-7` · позиционирование `p-relative/absolute/fixed/sticky` · `sr-only`, `truncate`, `pt-safe/pb-safe`, `overscroll-contain` и др.

**Анимации/hover:** `hover-80`, `hover-none`, `translate_0_2`, `translate_0_5`, `scale_0_1`, `hover-rotate-15`, `active_scale_09/098`, `visibility-hidden/visible(.active)`.
**Правило про мобильные:** `:hover` **только** внутри `@media (hover:hover) and (pointer:fine)` — используйте `@use ".../mixins"` → `@include mixins.hover { … }`;
на тач-экране тот же эффект — `mixins.touch-press` (`:active`). На телефоне hover «залипает» после тапа — поэтому нельзя писать голый `:hover`.

**Мобильные фиксы в base:** input/select/textarea ≥16px на `pointer:coarse` (иначе iOS зумит), `touch-action: manipulation`, `text-size-adjust`, `dvh` вместо `vh`,
`prefers-reduced-motion`, видимый `:focus-visible`, `img{height:auto}`, `[hidden]{display:none!important}`.

**Проектный `style.scss` (правки владельца):** в `main` первая секция `section:first-of-type .container` получает `min-height: calc(100dvh - 200px)` (hero «почти во весь экран»)
и `h1 { font-size: clamp(30px,5.4vw,45px) }`; `.checks-li li::before` рисует галочку `✓` в синем кружке (нужен `li` с `p-relative pl-30`).
⇒ **первая `<section>` на странице всегда «раздута»**: на страницах со списком/поиском (`/sklad`) держать всё в одной секции.

**CSS Modules и SCSS:** `sassOptions.includePaths` **не** срабатывает для `*.module.scss` — миксины подключать **относительным путём**,
например `@use "../../../assets/scss/mixins";` (из `src/app/[locale]/test1/`). Внутри `_base.scss` и др. (в той же папке) `@use "mixins"` работает.
Неслойные стили модулей **сильнее** слоёв ReluxCode (в т.ч. базового `font-size` инпутов — при переопределении ставить 16px вручную).

## 14. Подводные камни и приёмы (для агента)

- **PowerShell и скобки:** путь `src\app\[locale]\…` — `[ ]` считаются шаблоном. Для `Remove-Item`/`Get-ChildItem` использовать **`-LiteralPath`**
  (без него `Remove-Item` молча ничего не удалит).
- Вывод PowerShell может показывать кириллицу «кракозябрами» — это консоль, файлы в UTF-8.
- **Устаревшие типы:** ошибки `tsc` про `.next/types/validator.ts` = хвосты старой сборки; лечится `Remove-Item .next -Recurse -Force` и повторным `tsc`.
- **Проверка сборки:** `npx tsc --noEmit` → `npx next build` → `npx next start -p <порт>` (порт менять: старые процессы держат порты). После проверок **останавливать серверы**:
  `Get-CimInstance Win32_Process | Where-Object { $_.Name -eq 'node.exe' -and $_.CommandLine -match '<порт>' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }`.
- **Сравнение SCSS «до/после»:** компилировать `ReluxCode.scss` пакетом `sass` (из `node_modules`) в CSS до и после правки и сравнивать правила через `postcss` (по ключу «контекст@media/@layer + селектор»).
  Скрипт лежал во временной папке сессии (не в репозитории) — при необходимости написать заново (≈40 строк).
- **Встроенный браузер Claude:** скриншоты при прокрутке в эмуляции нестабильны (обрезка, «замороженные» анимации — переходы `opacity/visibility` не продвигаются, пока не отрисуется кадр). Надёжнее проверять числами через JS
  (`getComputedStyle`, переполнение `scrollWidth > innerWidth`, размеры кнопок) и делать пару `screenshot` подряд. Для высокого окна помогает `resize_window` 1100×1600; после проверок вернуть `preset: desktop`.
  Эмуляция `mobile` даёт `hover:none / pointer:coarse` — так проверялись правила ReluxCode. Куки-баннеры на чужих сайтах не нажимать.
- `Edit` требует **уникальный** `old_string`; после `Write` нового файла повторный `Read` не нужен, а для чужого/изменённого — нужен.
- Правки `messages/*.json` массово удобно делать Node-скриптом (JSON.parse → изменить → `JSON.stringify(…,null,2)`), сохраняя LF и 2 пробела.
- Next.js docs: `node_modules/next/dist/docs/01-app/…` (например `02-guides/internationalization.md`, `03-api-reference/04-functions/next-root-params.md`).
